整体改造

整站鸟瞰见 总览 · 三问导读。本页是站级蓝图（智能化方向）：把「智能化」从单点脚本扩展为六域协同（数据、管道、分析、前端、运维、治理），并与 智能进化（模型/RAG 分层、§11 插槽⑨）对齐。闭环与插槽的概念总览见 可进化架构。目标不是一次性大重构，而是可验收、可分期的改造清单；定性脚手架与人工闸门不变。

1. 目标与原则

  • 目标：在保持可审计、可离线归档的前提下，提升「观测 → 编码 → 分析 → 反哺」的吞吐与一致性，并为模型/RAG 预留标准接口。
  • 非目标：全自动改 HTML、无人审 merge、对读者隐藏不确定性。
  • 接口纪律：站内核仍以 evolution-manifest.json、analysis-snapshot.json 等为契约；智能层产出走候选/sidecar/工单，见 智能进化 · 边界。

3. 六域改造视图

  • 数据域：信号、沉淀（sediment.json + data/evolution.db 双写）、人审决策、站内语料指针；所有自动化写入须可回滚。
  • 管道域：ingest →（可选智能预处理）→ candidates → 人审 → manifest；与 进化闭环 · 抓取 同构扩展。
  • 分析域：快照 + 规则提示 +（可选）LLM 工单草案；分析引擎 为统一读出口。
  • 前端域：沙盘、信号栏、分析仪表盘、未来「工单/候选」面板共用设计 token（assets/site.css）。
  • 运维域：静态托管不变；增加 secrets、定时、观测（日志/告警）即可支撑生产级智能步骤。
  • 治理域：与 战略·舆情、§2 判据 对齐；重大改版走 PR + 人工阅读 diff。

5. 三期里程碑

阶段焦点交付物（示例）
P0 夯实 可重复、可观测 沉淀双写 + 趋势脚本 + 一键流水线（已部分落地）；决策日志 schema；analysis_engine --dry-run（待加）；前端错误态统一
P1 智能层 候选侧车 + 轻量模型 *.suggestions.json 或 manifest 扩展字段；摘要/映射 API；校验器与 PR 模板
P2 闭环学习 RAG + 评测 站内语料索引；离线基准集；采纳率/幻觉率看板（可外置仪表盘）

6. 工作包 WBS（编号便于跟踪）

  • W1 决策日志：候选 id、操作者、通过/驳回、备注 → 单文件或 SQLite 新表（与现有 sediment_entry 并列）。
  • W2 语料切块：对关键 HTML/§11 导出块，生成 chunk_id → 路径#锚点 表。
  • W3 ingest 插件点：在写入 candidates 前调用「清洗器」接口（规则或 HTTP 内网服务）。
  • W4 analysis：dry-run、工单 JSON（仅建议）与 snapshot 分离。
  • W5 前端：evolution.js / analysis.js / site-data-bus.js 共用 fetch 封装与错误提示。
  • W6 配置：.env.example 文档化 API Key 与「仅 P1 启用」开关。
  • W7 定时：bash scripts/run_update_pipeline.sh；GitHub Actions 见 .github/workflows/update-pipeline.yml（artifact）；ingest 单独排期。
  • W8 安全：密钥不进仓库；外调模型日志脱敏策略。
  • W9 评测：固定信号集 + 期望标签（JSON），CI 或本地一键跑。
  • W10 RAG（P2）：向量库选型与最小流水线。
  • W11 文档：本页与 智能进化 交叉维护「路线图」段落。
  • W12 沙盘：智能仅建议默认勾选，持久化读者选择为可选 localStorage。

7. 与综合推演 §11 插槽

§11 中 ⑦⑧⑨ 已覆盖 manifest 管道、分析引擎与智能分层；本页对应扩展插槽 ⑩：把智能化当成跨页工程，按上表 WBS 与 P0—P2 推进，避免只在单脚本打补丁。

读法：落地时以工作包拆任务；每期结束检查「是否增加可观测性」与「是否收紧闸门」，再进入下一模型层级。

8. 度量与验收

  • 工程：CI 绿、校验脚本覆盖 manifest/candidates/sidecar。
  • 质量：候选→正式库采纳率、工单人工修改比例（模型输出被改多少）。
  • 读者：沙盘/分析页在 HTTP 下首屏可用（无白屏无静默失败）。
