进化闭环：让推演随观测「长出来」

整站鸟瞰见 总览 · 三问导读。本页定义自动进化在本站中的含义：不是替代人类判断的预测机，而是可重复的观测—编码—反哺管道——脚本从 RSS、法规/政策索引页等拉取线索，汇总为 assets/evolution-candidates.json（待审），人审后再并入 assets/evolution-manifest.json；前端 evolution.js 同时展示已入库与候选，并合并 lab_factors 驱动沙盘高亮。人机分工：机器可做抓取、去重、关键词路由；法理判断与是否升格为站内核仍须人审。面向社会责任取向的多源信号（舆情/战略/商业等）与推演输出见 社会责任 · 可进化推演。

观测 — 信号入库（含来源类型与权重） 编码 — 映射到页、配方、lab_factors 反哺 — 触发 §11 扩展或新配方/表行
OODA 闭环 清单格式 抓取管道 自动化边界 人必须做什么 当前信号

1. OODA 与全站对齐

借用观察—判断—决策—行动的节奏，但本站决策落点是「是否改站、改哪一页、是否增配方」而非企业 OKR。

  • Observe：从 战略·舆情 双轨、媒体/平台议程、部委征求意见、招标条款、事故链等收集可复述事实（忌只存标题党）。
  • Orient：用 §2 判据 与 五系七层 给信号找「邻居模块」——避免孤立热词。
  • Decide：信号是一次性注释还是值得进 §6 配方 / §7 表行 / 沙盘因子 提示。
  • Act：更新 manifest 或候选文件；必要时改 HTML 正文；版本控制留下 diff；读者在 沙盘 与 战略·舆情 · 信号栏 看到结果。

2. 清单文件：evolution-manifest.json

单文件、可版本化；字段经 scripts/validate-evolution-manifest.py 校验。

字段含义
schema_version当前为 1；大改结构时递增
updatedISO 日期，便于与十年窗对时
signals[]多条观测信号
id全站唯一
kindopinion（舆情） / policy / law（法律或条文线索） / market / tech
weighthigh | medium | low — 影响沙盘高亮优先级
maps_to.pages建议先读的站内页（相对路径）
maps_to.lab_factors与 lab.js 中因子 id 一致时，沙盘勾选区高亮

扩展：可在 maps_to 中自增 synthesis_recipe 等键，但须同步改 assets/evolution.js 才会在页面上显式展示。

3. 抓取管道：舆情 RSS、法规页标题与候选汇总

配置 scripts/ingest_config.json：列出 rss_feeds（标题/摘要/链接）与可选 law_html_pages（仅抓页面 <title> / og:title 作线索，非全文法条）。脚本按 routes 正则把文本路由到站内页与 lab_factors，去重后写入 assets/evolution-candidates.json。可选 require_route_match：true 时只保留至少命中一条 route 的 RSS/法规项，并移除候选池中历史遗留的未命中项（减噪）。

在项目根目录执行：（等价：bash scripts/run_ingest_only.sh 或 make ingest；脚本一览见 scripts/README.md）

python3 scripts/ingest_opinion_law.py
python3 scripts/ingest_opinion_law.py --full-pool   # 单次全量进池（忽略 require_route_match）
python3 scripts/validate-evolution-candidates.py

审阅候选后，将指定 id 合并进正式库：

python3 scripts/merge_candidates_to_manifest.py ing_xxxxxxxxxxxx
python3 scripts/validate-evolution-manifest.py
python3 scripts/analysis_engine.py --sediment

定时进化：在 CI 或 cron 中跑抓取（make ingest），对 evolution-candidates.json 开 PR，勿自动 merge 进 manifest。GitHub Actions 可手动 Run workflow：ingest-pipeline.yml（artifact 下载候选）。分析侧与抓取解耦：bash scripts/run_update_pipeline.sh（make analyze），见 分析引擎。持续更新详见 分析引擎 · §6。双周反哺见 运行手册；PR 合并 manifest/候选前请跑通 make validate（含 check_manifest_drift.py 对账）。

合规：遵守各站点 robots.txt 与版权；法规正文以权威发布机关页面为准，本管道仅作线索聚合，不构成法律意见。

4. 自动化能做什么（边界）

若计划引入大模型或检索增强，见 智能进化 的分层、数据治理与路线图（§11 插槽⑨），与下表互补。

  • 可脚本化：定时拉取 RSS/开放 API、关键词聚类、去重、生成候选 JSON 片段；CI 跑校验脚本后开 PR 而非静默上线。
  • 可做前端：evolution.js 读取 manifest，渲染信号栏、沙盘因子高亮（需通过 http(s) 访问站点，file:// 下 fetch 可能失败）。
  • 不宜自动化：把「热搜」直接写成「国家意志」；省略 §2 判据；未经人工审核就改配方正文。

5. 人必须做什么（站内核纪律）

与 综合推演 §11 纪律一致：每条入库信号应能回答——若不能，留在私有笔记，不进 manifest。

三问（入库前）：能否指回 §2 判据之一？能否映射到至少一个模块页或沙盘因子？若发酵消失，是否仍值得保留为「历史切片」？

扩展插槽 ⑦（§11）：manifest 新增信号 → 沙盘高亮 → 推演一轮 → 决定是否升格为 §6 配方 / §7 表行 / 教育页案例句；见 §11 列表。
