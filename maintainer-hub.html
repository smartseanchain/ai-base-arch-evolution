维护导读：管理端入口与文档

本页不替代 Git 与 PR 流程，仅汇总维护者 / 数据管家常用入口：分端设计、合并闸门、文档主线与契约。若你其实想只读站，先到 总览 · 四条动线 或 README · 四条动线 定角色；读者主链仍以 读站指路 与 进化闭环 为准。manifest 人审、分析不写 HTML 等不变量见 AGENTS · 人审闸门 · 架构边界 与各专篇文档。

你多半是：维护 / 合 PR → 下文与 CONTRIBUTING · 开 PR 前速览 · PR 证据三联 · 动手→命令速查 · make validate；只想读站 → 总览 · 读站指路；看分析读数 → 分析引擎。

站内 docs/*.md 在根部署下可能为原文或下载；长文建议在仓库网页阅读或克隆后本地打开。

本地预览读者 MPA（总线 fetch 须有 http）：仓库根 make serve-reader → 127.0.0.1:8000，或 make docker-up / compose → 8765；勿仅用 file:// 双击 index.html。详见根 README.md · DOCKER.md。

合并前推荐 make merge-ready（validate + 只读 API + 管理端烟测），见下链。

读者面/管理面速查：PLATFORM_MASTER_MAP（reader-admin-surfaces） · 衔接矩阵 · 场景×面；下文「衔接矩阵（站内速览）」与「读者面（前端）与管理面（后端）」有展开链。

跨 PR 架构收束：ARCHITECTURE_ONE_PAGER · 五步表（粒度 · 真源 · 闸门 · 演进 · 节奏；与 PLATFORM_MASTER_MAP 总表互补）· 不变量索引（五条红线） · 开 PR 前速览 · PR 证据三联 · 动手→命令速查。

系统边界速查

判型与合入时「哪儿是人编真源、哪儿是生成物、哪儿可重建、哪儿不能自动写」；细节以链上专篇为准。

  • 人编真源：根目录 *.html 叙事、partials/ 顶栏与 skip 模板、scripts/evolution-registry.json、docs/ 与 docs/schemas/ — docs/README · 真源分层（#content-framework） · PROJECT · §1b 物理分层。
  • 生成 / 同步产物：spa/src/navLinks.ts（make gen-nav-links）、spa/public/（make spa-sync / make spa-build）— MERGE · §1（pre-merge） · MERGE · partials 手顺 · spa/README。
  • 侧车可重建：data/evolution.db、本地 artifacts/ 遥测等 — EVOLUTION_RUNBOOK · SQLite · ONE_PAGER · 五步表（与侧车/闸门节奏对读）。
  • 合并不变：bash scripts/run_validate.sh / make validate 为 CI 与 pre-commit 真源；make test、make validate-fast 不替代合并前全量 — ARCHITECTURE · run_validate · AGENTS · 合并前。
  • 手调例外：404.html、legacy-all-in-one.html 不经 sync_site_nav；改 partials/skip-bar.inc.html 后须手调 404 / legacy，并跑 make validate（含 check_skip_bar_404.py 与 skip 对表单测）— scripts/README · sync_site_nav / 真源。
