维护导读：管理端入口与文档

本页不替代 Git 与 PR 流程，仅汇总维护者 / 数据管家常用入口：分端设计、合并闸门、文档主线与契约。读者仍以 读站指路 与 进化闭环 为主链；manifest 人审、分析不写 HTML 等不变量见各链文档。

站内 docs/*.md 在根部署下可能为原文或下载；长文建议在仓库网页阅读或克隆后本地打开。

合并前推荐 make merge-ready（validate + 只读 API + 管理端烟测），见下链。

读者面/管理面速查：PLATFORM_MASTER_MAP（锚 reader-admin-surfaces）；下文「读者面（前端）与管理面（后端）」一节有展开链。

推演扩展 · 本轮提要（维护导读）

新增顶栏「维护导读」一页：链向设计文档与闸门，不改变既有数据管道与校验语义。

读者面（前端）与管理面（后端）

前端：给读者看的枢纽、叙事、总线读数与沙盘——只读已发布内容。后端：本仓库脚本、CI、只读 API、Docker 与 PR 闸门——维护者与数据管家的操作面；不在站内页面里写 manifest 或绕过 make validate。

  • 分拆总览：前端读者 · 后端管理（节 1a）
  • 平台总览 · 读者面/管理面速查（PLATFORM_MASTER_MAP · 读者面/管理面）
  • 六域协同与读者面/管理面对齐
  • 管理端 Web 化路线图（登录、用户与角色、审核工作流、Git 审计、分阶段）

分端与能力设计（Markdown）

  • 用户端 / 管理端 · 数据源 · 进化与分析 · 审核分层
  • 扩展插槽、进化轨、智能化边界与检查单
  • 技术架构整理与升级路径（简版）
  • 智能化 · 六域协同（数据 / 管道 / 分析 / 前端 / 运维 / 治理）

闸门、合并与 CI

  • 合并与发布一页清单（make merge-ready）
  • 参与贡献与环境命令
  • 文档主线表（#docs-spine）
  • 只读 API 与 OpenAPI
  • Docker 部署（make docker-up / make docker-up-api / make docker-up-admin）
  • 管理端脚手架（本地 / Compose profile admin，端口 8100）
