读站指路

全站是定性脚手架：帮你对齐变量、传导与分叉，不代替你下结论。三条入口可并行，择一条深读即可。

顶栏链多不必慌记：可先抓住五枢纽——总览 → 立体联结 或 模块图谱 → 综合推演 → 分析引擎 → 沙盘工坊；其余从下方分区速跳或顶栏检索即可。

下方每个分区大标题下还有一行读后自问；可先读问题，再点卡片。不少卡片点开即落到页内关键节；多数页在该节之上仍有推演扩展 · 本轮提要，深链落地后仍建议快速过目。

文中链到 docs/*.md 的，在 GitHub Pages 等静态根部署下常为浏览器打开 Markdown 原文；若要渲染版式，请在 GitHub 仓库页打开同路径文件，或克隆仓库本地阅读 docs/。维护说明见 全站梳理 · 四角色复查。

克隆到本机后：总线 JSON（如 evolution.js 拉取的文件）须用 http:// 打开站点；勿仅用 file:// 双击 index.html。仓库根执行 make serve-reader 后访问 127.0.0.1:8000，或用 Docker 映射 8765；读者 / 贡献者入口与双轨说明见根目录 README · 从这里开始 · 双轨真源，运维快启见 DOCKER.md。

线上 / 子路径 / 可选 SPA：GitHub Pages 须在仓库 Settings → Pages 选对源与目录；默认以根目录 MPA 为主读形态，若要发布全站单页壳，构建前须设与仓库路径一致的 VITE_BASE（见 spa/README · GitHub Pages）。

  • 维护者 / 数据管家：写操作与闸门在 Git、脚本、CI（管理端/后端侧），不在站内静默改库；导读见 维护导读，一页内「本页 ↔ 注册表 ↔ 文档锚点」见 关系视图 · 系统边界 · 衔接矩阵（站内速览）；跨 PR 架构收束见 ONE_PAGER · 五步表 · 不变量索引 · PR 证据三联；分拆说明见 用户端/管理端 · 前端与后端，总览与全文矩阵见 PLATFORM_MASTER_MAP · 读者面/管理面速查 · 衔接矩阵 · 场景×面。读者仍以本页与 进化闭环 为主链。
  • 第一次系统读：三问导读 → 立体联结 或 模块图谱 → 五条判据 → 按下方分区卡片下钻。
  • 想押时间线与情景：历史 · 五代横轴、廿年 · 对照总表、十年 · 六维总表 / 阶段条、十年场景 · 矩阵；动手用 沙盘 与 继续推演矩阵 加压。
  • 想看读数与站内核如何迭代：分析引擎 · 方法与演进全景、进化闭环、可进化架构；推演纪律与偏误自检见 DEDUCTION_STRATEGY。
