智能进化：扩展梳理

整站鸟瞰见 总览 · 三问导读。本站已有规则化闭环：进化闭环（ingest → 候选 → 人审 manifest）与 分析引擎（热力 · 共现 · 沉淀）。本页把「智能进化」定义为：在不替代人审闸门的前提下，用模型、检索与评测减轻重复劳动、提高映射与摘要质量，并把决策日志化以便迭代。全文是架构与路线说明，不是现成产品规格。

边界 — 辅助 ≠ 自动改站 分层 — 规则 → LLM → RAG → 微调 衔接 — §11 插槽⑨ · 候选侧车

推演扩展 · 本轮更新（智能进化）

本轮重申：模型输出默认进候选或侧车；每条自动摘要须配「人审检查点」与回滚路径；对表 继续推演矩阵 智能+改造+架构行。

  • 分层（规则→LLM→RAG→微调）旁注哪一层可单独关掉而不伤站点真源。
  • 评测指标与 决策追溯 字段对齐，避免黑箱工单。
  • 与 进化闭环 对读：哪些字段只能人改 manifest。
  • §11 插槽⑨ 变更时同步更新 整体改造 WBS 中的智能子项。

1. 概念与边界

「智能」若只等于「自动」，容易与本站定性脚手架、可审计的定位冲突。建议采用三条纪律：

  • 智能层输出默认进「候选」或 sidecar（例如扩展字段、单独 JSON），经校验与人工确认后再影响 evolution-manifest.json 或 HTML 正文。
  • 可解释：映射到站内页、因子、配方时，应能给出「依据片段」或引用（RAG 尤其适合）。
  • 可评测：离线基准集 + 线上抽样复核，避免「感觉更聪明」却无法验收。
与「自我进化」的关系：进化闭环 解决信号从哪来、怎么入库；分析引擎 解决结构是否漂移；智能进化解决如何把人的时间从重复贴标签中省出来，并不自动宣布「站内核」已变。

2. 能力分层（由浅入深）

下列层次可叠用；越往下投入越大，越需要标注与评测闭环。

层级典型能力依赖本站落点（示意）
L0 规则与词典 关键词路由、正则、黑白名单、去重（SimHash 等） ingest_config.json、维护者时间 现有 ingest 管道
L1 传统 NLP 实体/主题粗分、聚类、语言检测 小模型或库，CPU 可跑 候选预处理、噪声过滤
L2 通用大模型（API） 摘要、多标签分类、JSON 结构化输出 API Key、提示词模板、输出 schema 校验 建议 maps_to.pages / lab_factors 的候选
L3 检索增强（RAG） 站内段落检索 + 外源摘要；带引用生成「建议修改点」 语料切块、向量库、embedding 流水线 反哺 §6/§7、§11 的草稿级建议
L4 排序 / 小模型微调 「是否升格 manifest」、候选排序、个性化权重 持续人审日志作训练信号 仅在数据够厚后考虑

3. 与现有管道对照

智能层插入点：在「原始抓取」与「写入 candidates」之间、在「merge 前审阅」、在「analysis 之后生成建议」三处最自然。

  • ingest 之后：去重、摘要、自动打标签 → 仍写入 evolution-candidates.json（或并行 *.suggestions.json），字段可含 model、confidence、rationale，由校验器约束类型。
  • merge 之前：人工界面或 PR 评论里展示模型建议，与规则路由对照；通过后才 merge_candidates_to_manifest.py。
  • analysis 之后：在 analysis-snapshot 之上增加「规则 + LLM」生成的行动提示单（例如：某因子连续 30 日 Top → 建议审阅 §7 某行），仅作工单，不直接改站。
沙盘侧：智能可建议默认勾选或高亮组合，读者仍可一键清除——与 沙盘工坊 的交互哲学一致。

4. 数据与治理

  • 统一信号 schema：在现有 manifest/candidates 上扩展可选字段即可，避免另起炉灶；大改时递增 schema_version。
  • 站内语料索引：若要做「建议改哪一段」，需要 HTML/§11 正文的切块与检索（向量或全文）；引用必须可回溯段落。
  • 决策日志：候选 id、模型版本、人审通过/驳回、合并者——是后续排序模型与复盘的基础。
  • 负例与拒识：标题党、重复、违规来源的丢弃记录，防止模型学偏。
  • 隐私与合规：外调 API 时原文是否脱敏、是否允许出境，需在配置层显式策略。

5. 工程与运维

主题说明
异步与队列embedding、批推理、长摘要不宜阻塞 ingest 或站点构建。
版本与开关按环境切换「仅规则 / 规则+模型」；模型名与 prompt 版本写入产出 JSON 元数据。
成本Token、向量库存储、CI 是否跑轻量校验 —— 分档配置。
运行环境前端 fetch JSON 仍需 HTTP；与 进化闭环 一致。

6. 路线图（务实四阶）

  1. 日志优先：人审结果结构化记录（即便尚无量产模型）。
  2. L2 试水：摘要 + 多标签 + 映射候选，强 schema 校验，全部进候选池。
  3. L3：站内 RAG，产出「带引用的修改建议」供 §11 工单。
  4. L4：有足够标注后再上排序/小模型，服务 merge 与工单优先级。

7. 风险与闸门

幻觉与议程：模型可能夸大某条信号与站内模块的相关性——引用与置信度展示 + 人审 双闸门。

与 进化闭环 · 自动化边界 一致：机器可做抓取与建议；法理判断、叙事升格、配方正文变更仍默认由人触发并通过版本控制留痕。

8. 与综合推演 §11 的衔接

在 §11 持续迭代 中，扩展插槽 ⑦⑧ 已覆盖 manifest 管道与 分析引擎。本页对应扩展插槽 ⑨：在 ⑦⑧ 之上引入可学习建议层（模型与检索），且默认写入候选/工单而非直接改站。

实施时建议：任何自动生成的「配方/表行」草稿须带 schema 校验 + PR 审阅 + 与 §2 判据的对照句，再并入正文。
